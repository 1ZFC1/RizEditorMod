# 变更记录

本文件记录实际完成的用户可见编辑器改动。研究结论和内部文档调整不冒充功能改动。

## 未发布（working 副本，2026-09-23，未进入任何版本包）

- **修复「项目」工具提示文本被其它功能改写**（D-032）：插件的公共状态出口（`SpeedEasePanel.ShowStatus`，缓动/剪贴板/缩放等都会用）此前**无条件**把同一句话写进「项目」body 的状态行，于是在画布流速里设定缓动后，项目面板的状态行会变成缓动文字。现在项目 body 的状态行与标题**完全自持**（`NativeProjectPanel` 自己的 `_status`，每帧重设），项目消息（切换成功/失败、槽位为空、选择文件…）直连自己的状态行，**两边互不影响**。已由使用者验收。
- **日志规范化**：写入规则改为「**信息尽量全、但只在动作/状态变化时输出**」。修复了上一改动引入的刷屏（`Refresh()` 每帧重写标题时，`SetAllTexts` 会逐组件打印 `'项目' -> '项目'`，一轮会话 1052 行里有 718 行是它）；现在文本/颜色**真的变化**时才记一行。同时把若干过简的日志补全细节：整体缩放（值/范围/步长/门闩/已保护画布数/相机正交与尺寸，每次动作一行）、项目 body 显隐（焦点画布/谱面/槽位/状态行）、状态行变化（旧→新）、游玩区域边框（屏幕矩形/世界边界/颜色/缩放）、预览蒙版隐藏（是否播放/是否带预览/开关）、跨画布剪贴板清空（丢弃的线数与节点数/源画布）。**没有任何每帧输出。**

- **「整体缩放」改为 40%–200%、每格 10 个百分点**（D-031）：`Ctrl+Shift+滚轮` 现在**可以放大**（此前被 `scale ≥ 0.999` 的判定挡住，只能缩小到 40%），步进方式由「每格乘 1.12」改为**加 10 个百分点**，共 17 档（40、50、…、200）；步进按 10% 栅格取整，不会漂移。放大与缩小共用「突破缩放极限」门闩，关掉即复位 100%。面板底部提示固定为「Ctrl+Shift+滚轮 整体缩放，Ctrl+M 复位。」。纯逻辑移入 `Core/ZoomStepping.cs` 并加自动测试（51/51）。已知：缩放状态下的 UI 点击偏移问题在放大方向同样存在。已由使用者验收。

- **新增「跨画布线的复制与粘贴」**（D-030）：一条线的节点可以分布在不同画布上，原版既选不中也粘不对（粘贴会把所有点压平到当前画布）。现在在线编辑里 **`Ctrl+C` 后按住 `Shift` 拖框**即可**整条线**选中：命中判定只看**当前画布**上被完全框住的节点，拖动过程中该线**实时高亮**，松开即结束。复制进插件自己的剪贴板（逐节点保留 `canvasIndex`），`Ctrl+V` 粘贴时按鼠标位置对齐、**每个节点画布整体偏移**（`目标画布 − 源画布`，Hold 的结束画布同步偏移，越界则放弃并提示），`Ctrl+Shift+V` 为**以鼠标为对称轴**的镜像粘贴；写入走 `EditControl.Stepping`，一次 Undo 可撤销。x 吸附跟随编辑器**水平细分**、拍吸附跟随垂直细分，换算用**实测渲染映射**（实测单位 5.625，旧常数 5.5625 偏 1.1%，已弃用）。剪贴板归属规则：最后复制者拥有剪贴板（原版复制后 `Ctrl+V` 粘原版内容）。不按 `Shift` 时对原版零干预。已由使用者验收，细节与失败记录见 `docs/features/CROSS_CANVAS_LINES.md`。

- **新增「游玩区域边框」**（D-029）：关闭「预览蒙版」并带预览播放时（或整体缩放不为 100% 时），用一个 **2px** 边框标出原本未被遮住、也就是游玩时实际可见的区域。边框颜色取谱面主题的 **UI 色**（`themes[0/1].colorsList[2]`，常规 RGB(179,144,179)、Riztime RGB(69,46,153)），因此随 Riztime 自动变色；四条边都取**世界固定值**（左右 = 侧板外侧边 ∓2.813、下 = `BottomSideForward` 上沿 −2.9、上 = `TopSide` 外侧边 +4.1）再经相机投影，所以**不随播放移动**、**随整体缩放与窗口变化**，而线宽恒定 2px。实现受本构建限制：`GUI.DrawTexture` 被 IL2CPP 裁剪（`Method unstripping failed`），故用自建 1×1 纹理 + 纯色 `GUIStyle` 配 `GUI.Box`，不可用时回退默认 `GUI.Box`。已由使用者验收。
- **缩放由「只改水平」改为等比（整体缩放）**（D-028）：`Ctrl+Shift+滚轮` 现在横竖同比例放大（`halfHeight = orthographicSize / factor`、`halfWidth = halfHeight × aspect`），不再把画面横向拉伸；范围仍 40%–100%、步进与触发条件不变。同时**删除 D-017 的「横向缩小时自动隐藏 editorMask」**（使用者实测无实际作用，预览播放时原版自己会关闭它）；右上角读数改为「缩放 N%」，面板底部提示改为「Ctrl+Shift+滚轮整体缩放，Ctrl+M 复位。」。已知仍存在：缩放后工具栏点击命中错位（自定义投影下 UI 画布须搬 Overlay），属另立任务。已由使用者验收。
- **新增「预览蒙版」开关**（D-027）：光标工具的「基础设置」面板多一行 `预览蒙版：开 / 关`（默认**开**＝完全保留原版行为）。切到**关**后，**带预览的播放**期间会隐藏编辑器 UI 画布上的深灰覆盖层（`blackMask`）以及游戏场景里遮住四周的侧板（`playMask` 两个主题组中**名字命中显式白名单**的 `TopSide`/`BottomSideForward`/`BottomSideBack`/`LeftSide`/`RightSide`，共 10 块），**背景色与其它一切照原样保留**，两侧与播放头以下（已过的拍）的谱面内容因此可见；停止播放或拨回「开」即恢复。面板高度 300→336。判据用**显式白名单**而不是名字后缀——后缀曾漏掉两块底部侧板，正是「播放头以下被盖住」的原因。原因与实测结构见 `docs/features/PREVIEW_MASK.md`：背景色就住在 `playMask` 里（其两个子物体正是 `ProjectInformation.backgroundColors`），所以**不能整组隐藏**，只能精确隐藏侧板。已由使用者验收。
- **修复：流速同拍重复导致「连删都删不掉」**。同一拍出现多个流速节点时，插件原来要求「严格递增」并直接拒绝，于是框选删除、复制、粘贴全部失败（提示「流速必须已按事件严格排列」）——数据越脏越修不了。现在**允许同拍重复、只拒绝时间倒序**（倒序时明确报出是哪两拍）；复制/剪切时把选区内的同拍项按「后一项优先」合并，粘贴前也折叠传入剪贴板中的同拍项，避免把重复继续传播；发现列表里已有同拍重复时，日志与状态行会列出拍号并提示可框选删除。同时修掉两处**重复来源**：① 流速缓动的密集采样在 float 精度下可能出现两个相邻采样落在同一拍（原来只过滤「塌缩到端点」的采样）；② 粘贴覆盖判定用 `1e-6`、插入用 `1e-5` 的容差不一致，导致距目标拍 5e-6 的既有节点没被覆盖而和新节点并排同拍。
- **修复：「编辑线」`Ctrl+D` 后线的颜色信息丢失**。`Line` 恰好有四个数据字段（`linePoints`/`notes`/`judgeRingColor`/`lineColor`），而插件的线剪贴板结构只保存了前两个；`Ctrl+D` 的「快照 → 原版 CutLines → 写回快照」因此用**残缺快照**覆盖了编辑器自己的线剪贴板，两个颜色数组被抹掉，之后粘贴出的线也没有颜色事件。现在四个字段全部捕获与重建；系统剪切板的线导出/导入也带上 `lineColor` / `judgeRing` 两段（旧文本没有这两段仍可解析，只是颜色事件为空）。
- **修复：在数值框里输入 `9` 会跳到「项目」工具**。`9` 由插件自己处理（原工具栏的键位映射覆盖不到运行时新建的按钮），但原来的处理没判断「是否正在编辑输入框」。现按项目既有做法统一到 `ProjectInformation.isInput`（`Ctrl+M`、`Ctrl+C/X/V/D` 早已如此），输入框聚焦时忽略该快捷键并记录一行日志。
- **弹性缓动扩展到「编辑摄像机·横向移动」**（D-023 范围定稿）。摄像机的缓动下拉与画布接线不同，因此改在 `Dropdown.set_value`（属性 setter）处**事件式拦截**：插件在编辑器自己的监听器之前拿到用户的选择，拟合曲线后把下拉值换成 `Linear` 再交回原版，非法索引永不写进谱面；画布仍走已验证的 `OnEaseTypeChange`。写入目标只能是 `cameraMove.xPositionKeyPoints`，与画布共用同一套拟合核心（容差、节点数、单步撤销一致）。
- **摄像机缩放取消**：使用者在缩放列表上选插件曲线后出现 `[Error : Unity] IndexOutOfRangeException`——`GetEase.EaseInfors` 只有 `19×101`，而缩放那条下拉当时没被拦住，游戏把 `19` 写进关键点后求值越界。现在选择缩放时只提示不支持、**不写入任何字段**，缩放保持原版行为。
- **新增越界缓动安全网**（`EaseTypeGuard.cs`）：`GetEase.GetEaseWithProgress` / `GetEaseWithIndex` 遇到 `easeType` 超出 0–18 时按 **Linear** 求值（与原拟合节点的语义一致）并告警一次，编辑器不再因坏数据崩溃；正常 0–18 的求值完全不受影响。
- **「编辑线」的弹性缓动最终取消**：实现（写入选中线节点的 `linePoints`，x 按曲线、颜色在两端点线性插值）经使用者实机试用后判定与操作习惯割裂——线工具靠拖动创建线、`Ctrl`+拖动改节点属性，下拉框驱动的拟合过于突兀。现已整体移除，线工具恢复原版行为；若将来重做，入口需与拖动交互一致。
- 「项目」工具（原「插件」工具栏入口）的界面改为**克隆原编辑器工具 body** 搭建：容器克隆 `编辑画布` 的 `Body`，槽位与「选择文件…」克隆其原生按钮，标题栏白字「项目」（框宽按文字+留白自适应）、行文字黑色并自动缩放/截断。位置、尺寸、标题框与字数上限都可改 `BepInEx\config\RhythmEditorMod\layout.json`（重启生效，未知键会告警）。面板**选中该工具即显示，不跟随鼠标**；工具栏原生的悬停淡出与再点锁定行为已实测记录，但复刻或托管都会让面板淡出后无法用鼠标进入，故未采用（见 `docs/features/PROJECT_SWITCH.md` 5.2）。已由使用者验收（「可以了，目前就这样吧」）。
- 「项目」工具栏入口有了正式用途：**编辑器内切换工程**（D-024）。面板显示最近三个工程（谱面 + 音乐），点击槽位即切换，无需退出重进；另有「选择文件…」直接调用原版的两步对话框（先谱面、再音乐）。切换前若当前谱面有未保存改动会先自动保存（复用原版 `FileControl.Save`，它本身会先跑自动保存）；从未保存过的新工程会被拒绝并提示，不会弹「另存为」。切换复用原版的快捷通道 `OpenLastProject()`（把目标路径写入 `PlayerPrefs` 的 `lastFilePath`/`lastSongPath`），读取、反序列化、音乐加载与自动保存基线全部走原版逻辑；完成后清理上一次遗留的 `%TEMP%\tmpXXXX.tmp` 音乐缓存（仅限系统临时目录下的 `.tmp`）。槽位存在 `BepInEx\config\RhythmEditorMod\projects.json`（明文可查看可手改）；状态行会显示「已打开：<谱面> + <音乐>」。已由使用者验收。
- 新增画布弹性缓动「拟合」（D-023）：在「编辑画布」的缓动下拉框末尾追加 `In Elastic`、`Out Elastic`、`InOut Elastic` 三项（命名沿用原编辑器风格），选中后把对应曲线烘焙成 `easeType = 0` 的普通节点写入当前播放头所在区间。三条曲线均为标准弹性式（`Out` 为使用者给定公式，`In` 与 `InOut` 取自同一标准族，并由 `In(x)=1−Out(1−x)`、`InOut(x)+InOut(1−x)=1` 两条性质在自动测试中锁定）。节点位置**按曲线弯曲程度自适应**（四分点弦误差细分），不再对齐拍线网格：默认容差下 2 拍区间约 21–25 个内部节点，而同样精度均匀网格需要数百个，平坦尾段不浪费节点。整段只占一个 Undo 步骤。原因：新缓动只能编辑器内自用——`GetEase` 的缓动表固定 19 条、`easeType ≥ 19` 会抛异常，游戏也只认这 19 种，所以曲线必须以已有 Linear 节点表达。
- 新增插件自己的工具栏入口「插件」（D-022）：运行时克隆「光标」按钮并追加到工具栏末尾，标题「插件」，面板按对象身份路由，当前内容为占位（本次只做机制验证）。快捷键 `9` 由插件自己处理——原工具栏的键位映射在启动时确定，覆盖不到运行时新建的按钮。过程中修正一处长期无效的代码：`GetComponentInChildren<T>(bool)` 在本构建必抛 `VerificationException`，组件查找改为「遍历子树 + `GetComponents<Component>()` + `TryCast<T>()`」。已知外观项：图标仍是光标的箭头。已由使用者在 working 副本验收（标题、鼠标点击、快捷键、互斥）。
- 修复「发布统计」永不显示、且选中「发布」却弹出「基础设置」的回归（D-021）。根因：`Publish` 按钮的 `toolObject` 实测为 `null`，而 0.3.0 的发布判定要求 `toolObject` 非空，因此恒为假；该按钮同时因 `toolObject == null` 被光标判定命中。现按按钮结构区分：`toolObject == null` 且有直接子物体 `Body` = 发布（谱面统计），没有 `Body` = 光标（基础设置）；`PublishControl` 只在选中按钮子树内作附加确认，不做全场景查找。工具切换日志扩展为按钮名、toolObject、`Body`、`PublishControl` 与最终面板。
- 已在 `RhythmEditor_working` 由使用者验收。`RhythmEditor_modded` 仍为 **0.3.0**，未包含这些改动。

### Editor changes

- 增加可按当前垂直细分把两个画布流速端点展开为离散缓动节点的面板；缓动类型以下拉框选择，名称与原版缓动栏一致（如 `Out Quad`）。超过 4096 节点会警告。插入时过滤 float 塌缩到端点的内部采样，避免首位拍双写速度事件。
- 增加当前拍流速端点捕获，不依赖原编辑器选中流速标签。
- 增加复用原矩形框的画布流速复制、剪切、原拍粘贴和播放头对齐粘贴；剪切保护首节点；粘贴覆盖同拍。
- 增加画布事件框选复制/剪切；`Ctrl+V` 最早事件对齐鼠标，`Ctrl+Shift+V` 同锚点左右镜像。
- `Ctrl+D`：框选删除且不写入软件剪贴板（流速/画布事件/颜色/摄像机/线）。Il2Cpp 回调用堆对象传递删除标志，线剪贴板深拷贝后还原。
- 一键把谱面颜色写入 `ProjectInformation.colorPanels`（画线、颜色编辑、主题编辑）；只填空槽。
- 「突破缩放极限」默认关闭。打开后音符流速可到 -0.5，并允许 `Ctrl+Shift+滚轮` 横向缩小（**40%–100%**）；`Ctrl+M` 复位。横向缩小时界面画布改 Overlay 保可视；小于 100% 时自动隐藏 `editorMask`。
- 「突破缩放极限」「预览细线」及面板宽度/透明度滑条改在**光标**工具的「基础设置」面板显示（原在音符编辑，见 D-018）；音符编辑无插件面板；**发布**只显示谱面统计。发布检测只认当前工具栏 `toolObject`。切换工具时新增一行 `已选择工具：按钮 <按钮名>，toolObject <toolObject 名>` 日志，用于诊断工具识别（光标是唯一没有 `toolObject` 的工具，见 D-018）。**已知缺陷**：该发布检测恒为假，0.3.0 中发布统计从不显示且「发布」被误判成「光标」，修法见上方未发布条目与 D-021。
- 预览细线：带预览播放时线宽约 75%。
- 系统剪切板导出开关与手动导入（空格/制表符均可）；线在导出开启时随原版复制/剪切写出。
- 颜色编辑的复制/剪切改为按框选矩形相对**大地 x=0** 的横向位置路由：整体在左侧只取线色覆盖，整体在右侧只取判定环，跨过 x=0 两者都取；拍数范围仍只看框选上下端（D-019）。
- `Ctrl+V` / `Ctrl+Shift+V` 的锚点语义不变，但粘贴哪个数组改为跟随「上一次真正复制到内容的那次复制」。
- 颜色粘贴改为**覆盖**目标拍：同拍已有的全部事件塌缩成一条，避免同刻规则下旧事件取胜而改变渲染颜色；粘贴块最后一条的 `endColor` 重定向到目标位置，不再把源谱面选区之外的过渡带进来（D-020）。
- 修复颜色写入被钳成纯白：`ColorKeyPoint.startColor` / `endColor` 与 `LinePoint.color` 的 interop 类型是 `Color32`（0–255），构造 `Color` 会被隐式转换钳成 `(255,255,255,255)`。该缺陷同时影响线剪贴板还原的节点颜色（D-020）。
- 修复颜色复制整体失败：`ColorEditor.editingLineColor`（`Nullable<bool>`）经 interop 读取会抛 `NullReferenceException`，原先被 catch 成静默回退并在后续抛错；颜色路径已不再读取该属性（D-019）。
- 颜色工具下拦截原编辑器的 `CopyColors` / `PasteColors`，避免两边同时写入造成同拍重复；没有聚焦画布时插件拒绝开始框选并提示，同时放行原编辑器动作。
- 摄像机移动框选同画布移动，不含缩放。
- 插件面板挡住鼠标时跳过画线落点。
- 修复画线/线色共享 `OnEnable`（RVA `0x2CF1D0`）双挂导致的卡死。
- 修复画布粘贴坐标与剪切后越界误报；绕开 IL2CPP `Nullable<Vector2>`。
- 批量修改进入单个 Undo/Redo 步骤；不写自定义 JSON 字段。
