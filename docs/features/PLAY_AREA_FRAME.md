# 游玩区域边框（`PlayAreaFrame`）

状态：**已实现并验收**（2026-09-24）。相关：`DECISIONS.md` D-029、D-028、`CHART_FORMAT.md`（主题色 `colorsList`）。

## 1. 需求

关闭预览蒙版时，用一个**长方形边框**标出「原本未被遮住、也就是游玩时实际可见」的区域。

约束（使用者给定）：

- 颜色跟随**主题 UI 色**，Riztime 时随之变色；
- **不随播放移动**、不受流速影响；
- 随**整体缩放**与**窗口变化**；
- 线宽固定 **2px**（不随缩放变粗）。

## 2. 绘制时机

| 条件 | 目的 |
| --- | --- |
| `预览蒙版：关` **且** 带预览播放 | 蒙版被抑制时，用框标出原本会被遮住的区域 |
| **整体缩放 ≠ 100%** | 缩小状态下随时可看 |

实现挂在 `SpeedEasePanel.OnGUI` 的**早期**（与右上角 `缩放 N%` 同级），因此不受插件面板 F8 显隐影响。

## 3. 几何：世界固定值 + 投影

| 边 | 来源（`playMask`、`editorMask` 两个根里取最外/最内） | 世界值 |
| --- | --- | --- |
| 左 / 右 | `LeftSide.min.x` / `RightSide.max.x` 的**外侧**边 | ∓**2.813** |
| 下 | `BottomSideForward.max.y` | **−2.9** |
| 上 | `TopSide.max.y` 的**外侧**边 | **+4.1** |

四条边都是**世界固定值**，再用 `camera.WorldToScreenPoint` 投影成屏幕矩形；`playMask` 是相机子物体，所以相机在播放中移动时框不动。

- **为什么下边排除 `BottomSideBack`**：它的上沿是 −1.9，比真正的下边界高 1 个世界单位；而 `editorMask` 根本没有这个子物体——这正是当初「候选 B 的下半部分看起来对」的原因。
- **为什么左右取外侧边**：它们与 `blackMask`（屏幕空间的两片 UI 遮罩）露出的区域 **100% 缩放下几乎完全一致**（世界 ±2.813 ↔ 608 px，实测差 1 px），但 `blackMask` 是**屏幕空间**的，不会随整体缩放变化；世界外侧边则会随之缩小，符合「随整体缩放同比变化」的要求。
- **为什么上边是 +4.1 而不是相机可视顶 +5**：使用者实测后要求取 `TopSide` 的外侧边（与左右同口径）。若取相机可视顶，则框的上边界永远等于屏幕最上沿、缩放时不动，与要求矛盾。

## 4. 颜色

`themes[inChallengeTime ? 1 : 0].colorsList[2]` —— 谱面主题里的 **UI 色**（`CHART_FORMAT.md`：`[0]` 背景、`[1]` 音符、`[2]` UI）。

- 通道是 **0–255**（交叉验证：`themes[0].colorsList[0]` = (190,185,204)，与实测背景色完全一致），因此写 `GUI.color` 前**除以 255**。
- 实测值：常规 **RGB(179,144,179)**、Riztime **RGB(69,46,153)**。
- 无谱面 / 色表缺失时回退白色并静默跳过。

## 5. 绘制路径（本构建的硬约束）

实测：**`GUI.DrawTexture` 在这个 IL2CPP 构建里被裁剪**——

```
[画框] 在第「绘制四条边框」步失败：NotSupportedException：Method unstripping failed
```

`GUIContent(Texture)` 构造函数同样不存在。可用的只有 `GUI.Box` / `GUI.Label`（插件面板一直在用 `GUI.Box`）。因此边框按下列顺序择优，并把结果记一次日志：

1. **自建 1×1 白纹理 + 纯色 `GUIStyle`** → `GUI.Box(rect, "", style)`（纯色、2px）；
2. 该重载不可用 → `GUI.Label(rect, "", style)`；
3. 都不可用 → **默认 `GUI.Box(rect, "")` + `GUI.color` 着色**（一定可用，但会带默认样式的边框/半透明）。

注意：**线宽固定在 2px**，与缩放无关；框的位置与尺寸才随缩放变化。

## 6. 迭代记录（三次候选）

1. **候选 A（`playMask` 内侧，世界 ±1.812 / −1.9…3.1）** → 太小，被排除。
2. **候选 B（`editorMask` 内侧，−2.9…3.1）** → **下半部分正确**，正 y 与左右不正确。
3. **候选 C（相机整屏）** → 排除。
4. 依使用者反馈定稿：左右取世界**外侧**边（与 `blackMask` 一致）、下取 `BottomSideForward` 上沿、上先试「相机可视顶 +5」→ 使用者指出「正 y 不会随整体缩放」→ 改为世界固定值，再按使用者要求取 **+4.1**。验收通过。

## 7. 兼容性与风险

- 绘制是纯叠加（IMGUI），不修改任何游戏对象、不写谱面。
- 缺遮挡块时该项不画并静默返回；纹理/样式创建失败自动降级；异常只记一次日志，不会刷屏。
- 若将来原版更名或移除这些节点（`TopSide`/`BottomSideForward`/`LeftSide`/`RightSide`），框会停止绘制并记日志，不会报错。
