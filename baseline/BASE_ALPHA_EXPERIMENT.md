## 待验证模型

前两轮结果支持以下候选：

```text
w = lineColor.a / 255
finalRGB = baseRGB + w * (lineColorRGB - baseRGB)
finalA = baseAlpha
```

如果该模型正确：

- 左线基础 Alpha=0，应始终不可见，即使覆盖 Alpha=255；
- 中线应始终保持约半透明，但 RGB 从绿变成暗黄/橄榄色，再变成红色；
- 右线应始终完全不透明，并发生相同的 RGB 变化；
- 中、右两条线同一时刻应有相同 RGB，但透明度不同。

以上只是待验证预测，不是当前结论。

## 联合公式结论

本轮确认 `lineColor.a` 只控制基础 RGB 到覆盖 RGB 的混合权重，而最终对象 Alpha 由 `linePoints[].color.a` 保持：

```text
w = lineColor.a / 255
finalRGB = baseRGB + w * (lineColorRGB - baseRGB)
finalA = baseAlpha
```

这解释了：

- 基础 Alpha 0 的左线即使覆盖 Alpha 接近 255 也不可见；
- 基础 Alpha 128 的中线从绿变红，但始终保持约半透明；
- 基础 Alpha 255 的右线发生相同 RGB 变化，但始终不透明。

核心联合公式在基础 Alpha 取 0、128、255，覆盖 Alpha 取 0、128、约 192、约 255 的本次测试域内标记为 `confirmed`。整数舍入、越界通道和屏幕最终合成的精确舍入仍未知。

## 结论

- `linePoints[].color.a` 决定线对象的最终 Alpha：`confirmed`。
- `lineColor.a` 决定基础 RGB 到覆盖 RGB 的线性混合权重，不提高或降低最终对象 Alpha：`confirmed`。
- 基础 Alpha 0 会使线始终不可见，无法由不透明 `lineColor` 恢复：`confirmed`。
- 基础 Alpha 128/255 时，中、右线 RGB 同步变化，但分别保持约 128/255 的最终 Alpha：`confirmed`。
- 编辑器会在整体平移线时同步平移其颜色事件，并重算节点 `floorPosition`：本次操作 `confirmed`。

## 当前限制

本轮不测试沿线基础 Alpha 渐变、`judgeRingColor` Alpha、颜色边界不连续、同刻事件和倒序事件。视口左右边缘及判定线下方的额外淡出也不是颜色 JSON 的一部分，需要与对象自身 Alpha 分开处理。
